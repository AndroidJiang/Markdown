# 流式渲染机制详解

> 本文档详细介绍 AntFluid 的流式（打字机）渲染机制，包括 `PrinterMarkDownTextView` 的工作原理、渐变效果实现、以及各模块如何配合流式输出。

---

## 一、流式渲染概述

在 AI 对话场景中，服务端通过 WebSocket/SSE 逐块发送 Markdown 内容。AntFluid 的流式渲染将这些内容以"打字机效果"逐字显示，而不是等内容全部到达后一次性渲染。

### 核心控件

`PrinterMarkDownTextView` — 继承 `AppCompatTextView`，是流式渲染的核心 UI 控件。

### 两种渲染模式

| 模式 | API | 场景 |
|------|-----|------|
| **静态渲染** | `setMarkdownText(markdown)` | 一次性显示完整内容 |
| **流式渲染** | `startPrinting()` + `appendPrinting()` | AI 对话打字机效果 |

## 二、流式渲染完整流程

### 2.1 初始化

```java
PrinterMarkDownTextView tv = findViewById(R.id.markdown_view);
tv.init(MarkdownStyles.getDefaultStyles(), callback);
tv.setPrintParams(25, 1);  // 每 25ms 输出 1 个字符
```

### 2.2 开始输出

```java
// 首次收到内容
tv.startPrinting(content);
```

`startPrinting()` 内部流程：

```
startPrinting(content)
│
├── mOriginText = content                    // 保存原始文本
├── mMarkdownParser.setPrintingState(true)   // 通知 Plugin 进入流式模式
│   └── TablePlugin.onStreamOutStateChanged(true)   // 启用 Span 缓存
│   └── JLatexMathPlugin.onStreamOutStateChanged(true)
│
├── mParsedContentText = markwon.toMarkdown(content)  // 全量解析为 Spannable
│   └── processMarkdown → parse → beforeRender → visit → afterRender
│
└── printing(0, chunkSize)                   // 开始逐字输出
```

### 2.3 逐字输出循环 — `printing()`

这是流式渲染的核心循环：

```
printing(startIndex, chunkSize)
│
├── endIndex = startIndex + chunkSize
│
├── if (endIndex >= totalLength)
│   └── 全文输出完成
│       → setTextSafely(fullSpannable)
│       → 结束
│
└── else
    ├── 1. 截断 Spannable
    │   └── handleSpan(source, endIndex, endTag)
    │       → 从 mParsedContentText 截取 [0, endIndex]
    │       → 保留所有 CharacterStyle Span
    │       → 复制到 SpannableStringBuilder
    │
    ├── 2. 渐变效果
    │   └── gradiantColorAnimateText(endIndex, sb)
    │       → 末尾 10 个字符添加 OpacitySpan
    │       → 从不透明渐变到透明
    │
    ├── 3. 设置文本
    │   └── setTextSafely(sb)
    │       → markwon.setParsedMarkdown(textView, sb)
    │
    └── 4. 调度下一帧
        └── postDelayed(mPrintTask, interval)
            → mPrintTask 中调用 printing(endIndex, chunkSize)
```

### 2.4 追加内容

```java
// 服务端持续推送新内容
tv.appendPrinting(deltaContent, true);
```

`appendPrinting()` 内部流程：

```
appendPrinting(delta, append)
│
├── if (append)
│   └── mOriginText += delta          // 拼接到原始文本
│
├── mParsedContentText = markwon.toMarkdown(mOriginText)  // 全量重新解析
│   └── 注意：不是增量解析，而是完整的 parse + render
│
└── 继续从 mCurrentPrintIndex 位置输出
    └── printing(mCurrentPrintIndex, chunkSize)
```

### 2.5 停止输出

```java
// 用户点击"停止生成"
tv.stopPrinting("(已停止)");
```

```
stopPrinting(endMessage)
│
├── removeCallbacks(mPrintTask)        // 取消定时器
├── mMarkdownParser.setPrintingState(false)  // 退出流式模式
│   └── TablePlugin.onStreamOutStateChanged(false)  // 清空缓存
│
├── if (endMessage != null)
│   └── 追加结束文本到 Spannable
│
└── setTextSafely(finalSpannable)      // 显示当前已有内容
```

### 2.6 暂停/恢复

```java
tv.pause();   // 暂停定时器
tv.resume();  // 恢复定时器
```

## 三、渐变效果实现

末尾的"淡入"效果是流式渲染的视觉亮点：

### 3.1 OpacitySpan

```java
// fluid-markdown/.../span/OpacitySpan.java
public class OpacitySpan extends CharacterStyle {
    private final int alpha;  // 0-255

    @Override
    public void updateDrawState(TextPaint tp) {
        int color = tp.getColor();
        tp.setColor(Color.argb(alpha,
            Color.red(color), Color.green(color), Color.blue(color)));
    }
}
```

### 3.2 渐变计算

```java
private void gradiantColorAnimateText(int endIndex, SpannableStringBuilder sb) {
    int gradientLength = Math.min(10, endIndex);  // 渐变字符数

    for (int i = 0; i < gradientLength; i++) {
        int pos = endIndex - gradientLength + i;
        // alpha 从 255（不透明）到 25（几乎透明）
        int alpha = 255 - (255 - 25) * (gradientLength - i) / gradientLength;
        sb.setSpan(new OpacitySpan(alpha), pos, pos + 1,
            Spannable.SPAN_EXCLUSIVE_EXCLUSIVE);
    }
}
```

效果示意：

```
这是一段正在输出的文本内容，后面的字|逐|渐|变|淡|
                                 ↑ alpha=200
                                    ↑ alpha=150
                                       ↑ alpha=100
                                          ↑ alpha=50
                                             ↑ alpha=25
```

## 四、Span 截断处理

### 4.1 问题

将完整 Spannable 截断到指定位置时，需要处理跨越截断点的 Span：

```
[     BoldSpan          ]
Hello **world is beau|tiful**
                      ↑ 截断点
```

### 4.2 解决方案 — `handleSpan()`

```java
private SpannableStringBuilder handleSpan(Spanned source, int end, String endTag) {
    SpannableStringBuilder sb = new SpannableStringBuilder(source, 0, end);

    // 获取截断点处的所有 Span
    CharacterStyle[] spans = source.getSpans(0, end, CharacterStyle.class);

    for (CharacterStyle span : spans) {
        int spanStart = source.getSpanStart(span);
        int spanEnd = source.getSpanEnd(span);

        if (spanEnd > end) {
            // Span 跨越截断点 → 截断 Span 到 end 位置
            sb.setSpan(span, spanStart, end, Spannable.SPAN_EXCLUSIVE_EXCLUSIVE);
        }
    }

    return sb;
}
```

## 五、各模块的流式兼容

### 5.1 StreamOutStateObserver 接口

```java
// markwon-core/.../StreamOutStateObserver.java
public interface StreamOutStateObserver {
    void onStreamOutStateChanged(boolean isPrinting);
}
```

当 `PrinterMarkDownTextView.startPrinting()` / `stopPrinting()` 被调用时，`MarkdownParser.setPrintingState()` 会通知所有实现了该接口的 Plugin。

### 5.2 TablePlugin 流式处理

| 状态 | 行为 |
|------|------|
| 进入流式 | 启用 `mTableSpanCache`，按 `(tableIndex, length)` 缓存 `TableRowSpan` |
| 追加内容 | 复用已有行的 `TableRowSpan`，只为新行创建新 Span |
| 退出流式 | 清空 `mTableSpanCache`，后续渲染全部重建 |

### 5.3 JLatexMathPlugin 流式处理

LaTeX 公式渲染较耗时，流式模式下：
- 缓存已渲染的公式 Drawable
- 避免每次 `appendPrinting` 重新渲染已有公式
- 退出流式时清理缓存

### 5.4 ImagesPlugin 流式处理

图片异步加载在流式模式下需要特殊处理：
- 避免图片加载完成时触发 `setText` 与流式输出冲突
- egame_cloud_phone 中增加了 `startImageStreaming()` / `stopImageStreaming()` API

## 六、性能特征

### 6.1 全量重解析

每次 `appendPrinting()` 都会全量重解析整个 Markdown 文本。这是当前实现的主要性能瓶颈：

```
appendPrinting("新内容")
  → mOriginText += "新内容"
  → toMarkdown(全部文本)       // O(n) 完整解析
  → printing(当前位置, chunk)  // 从当前位置继续
```

**影响：** 长文本时每次追加都有明显开销，但由于追加频率受 WebSocket 消息间隔限制（通常 > 50ms），实际体验可接受。

### 6.2 Span 缓存优化

TablePlugin 和 JLatexMathPlugin 的 Span 缓存避免了重建开销最大的两类 Span。

### 6.3 定时器频率

`setPrintParams(interval, chunkSize)` 控制输出速度：
- `interval` — 每帧间隔（毫秒），推荐 20-30ms
- `chunkSize` — 每帧字符数，推荐 1-3

## 七、状态管理

### 7.1 打印状态

```java
enum PrintState {
    IDLE,       // 未打印
    PRINTING,   // 打印中
    PAUSED,     // 已暂停
    FINISHED    // 已完成
}
```

### 7.2 状态保存与恢复

支持通过 `MarkDownPrintData` 保存/恢复打印进度（用于 Activity 重建等场景）：

```java
// 保存
MarkDownPrintData data = tv.savePrintData();

// 恢复
tv.restore(data);
```

### 7.3 生命周期感知

`PrinterMarkDownTextView` 实现 `DefaultLifecycleObserver`：
- `onPause()` — 暂停打印
- `onResume()` — 恢复打印
- `onDestroy()` — 停止并清理

## 九、RecyclerView 列表中的流式渲染

### 9.1 ListActivity 示例

`app-sample/.../demos/ListActivity.java` 演示了列表中的流式渲染：

```java
// MarkdownHolder 中
PrinterMarkDownTextView markdownView;

void bind(MarkdownData data) {
    markdownView.init(styles, callback);
    markdownView.setPrintParams(25, 1);
    markdownView.startPrinting(data.getContent());
}
```

### 9.2 注意事项

1. **ViewHolder 复用** — `onViewRecycled` 时需要调用 `stopPrinting()` 停止定时器
2. **高度变化** — 设置 `SizeChangedListener` 通知 `RecyclerView` 重新测量
3. **缓存清理** — egame_cloud_phone 中发现并修复了复用时 TablePlugin 缓存未清理的问题
4. **maxWidth** — 需要通过 `setMaxWidthForMeasure()` 设置正确的宽度（RecyclerView 中宽度可能与全屏不同）

## 十、与 egame_cloud_phone 的差异

AntFluid 的流式渲染是基础版，egame_cloud_phone 做了以下增强：

| 功能 | AntFluid | egame_cloud_phone |
|------|----------|-------------------|
| 基础打字机 | `startPrinting` / `appendPrinting` | 同上 |
| 流式 Markdown | 无 | `renderStreamingMarkdown` / `finishStreamingMarkdown` |
| 图片流式 | 无 | `startImageStreaming` / `stopImageStreaming` |
| RecyclerView 复用修复 | 无 | 非流式时 `clear()` 全部缓存 |
| 深色主题 | 无 | 代码块/语法高亮深色适配 |
