# AntFluid 项目架构与设计思路

> 本文档帮助你从全局视角理解 AntFluid（AntFluidMarkdown）的架构设计，包括模块划分、解析→渲染完整流水线、以及 Plugin 扩展机制。

---

## 一、项目定位

**AntFluid** 是蚂蚁集团开源的 [FluidMarkdown](https://github.com/antgroup/FluidMarkdown) 项目的 Android 端实现，面向 AI 对话等场景，核心能力：

- 基于 **CommonMark** 标准解析 Markdown
- 基于 **Markwon**（自 fork 版本）将 AST 渲染为 Android `Spannable`
- 通过 `PrinterMarkDownTextView` 实现逐字/逐块**流式输出**（打字机效果）
- 样式通过结构化 `MarkdownStyles` 模型配置

**渲染方式：** 纯 Native `TextView` + `Spannable` + 自绘 `ReplacementSpan`，不是 WebView，也不是 Compose Canvas。

## 四、解析→渲染完整流水线

这是理解整个项目最核心的部分。从一段 Markdown 字符串到最终在 `TextView` 上显示，经历以下阶段：

```
    ┌─────────────────────────────────────────────────┐
    │         原始 Markdown 字符串                       │
    └────────────────────┬────────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────────┐
    │  [阶段1] processMarkdown()                       │
    │  各 Plugin 依次预处理原始文本                       │
    │  - CustomHtmlPlugin: highlight→span、\[\]→$$      │
    │  - DefinitionListPlugin: dl/dt/dd → HTML          │
    │  - MarkdownParser: $\bm{x}$ → ***x***            │
    └────────────────────┬────────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────────┐
    │  [阶段2] Parser.parse()                          │
    │  CommonMark 解析生成 AST（Node 树）                │
    │  扩展: GFM Tables, Strikethrough, TaskList,      │
    │        LaTeX Block/Inline, InlineParser           │
    └────────────────────┬────────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────────┐
    │  [阶段3] beforeRender(node)                      │
    │  各 Plugin 可修改 AST 树结构                       │
    └────────────────────┬────────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────────┐
    │  [阶段4] MarkwonVisitor 遍历 Node 树              │
    │  每个 Node 类型有对应 NodeVisitor                  │
    │  → 通过 SpannableBuilder 追加文本                  │
    │  → 通过 MarkwonSpansFactory 查找 SpanFactory      │
    │  → 附加 Android Span（颜色/粗体/背景/自绘等）       │
    └────────────────────┬────────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────────┐
    │  [阶段5] afterRender()                           │
    │  各 Plugin 渲染后回调（此时修改 node 已无效）        │
    │  → 得到完整 Spanned 对象                          │
    └────────────────────┬────────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────────┐
    │  [阶段6] beforeSetText / setText / afterSetText  │
    │  - beforeSetText: 准备 TextView（如取消旧调度）     │
    │  - setText: 将 Spanned 设置到 TextView             │
    │  - afterSetText: 图片 AsyncDrawable 注册、         │
    │                  表格行刷新调度等                    │
    └─────────────────────────────────────────────────┘
```

### 核心代码位置

解析+渲染的核心实现在 `MarkwonImpl.java`：

```java
// 阶段1+2: 预处理 + 解析
public Node parse(String input) {
    for (MarkwonPlugin plugin : plugins) {
        input = plugin.processMarkdown(input);  // 阶段1
    }
    return parser.parse(input);                  // 阶段2
}

// 阶段3+4+5: 渲染
public Spanned render(Node node) {
    for (MarkwonPlugin plugin : plugins) {
        plugin.beforeRender(node);               // 阶段3
    }
    final MarkwonVisitor visitor = visitorFactory.create();
    node.accept(visitor);                        // 阶段4
    for (MarkwonPlugin plugin : plugins) {
        plugin.afterRender(node, visitor);        // 阶段5
    }
    return visitor.builder().spannableStringBuilder();
}
```

## 五、Plugin 架构详解

Markwon 采用**插件链**架构，所有功能扩展都通过实现 `MarkwonPlugin` 接口完成。

### 5.1 MarkwonPlugin 接口

```
MarkwonPlugin 生命周期钩子
│
├── configure(Registry)          # 构建时最先调用，可通过 Registry 获取其他插件
│
├── configureParser(Builder)     # 注册 CommonMark 扩展、BlockParser
├── configureTheme(Builder)      # 修改渲染主题
├── configureConfiguration(Builder) # 注入全局配置（SyntaxHighlight、ImageLoader）
├── configureVisitor(Builder)    # 注册/覆盖 Node 访问逻辑
├── configureSpansFactory(Builder)  # 为 Node 类型指定 SpanFactory
│
├── processMarkdown(String)      # 解析前预处理 Markdown 字符串
│
├── beforeRender(Node)           # 渲染前修改 AST
├── afterRender(Node, Visitor)   # 渲染后回调
│
├── beforeSetText(TextView, Spanned) # setText 前准备
└── afterSetText(TextView)       # setText 后处理
```

### 5.2 AbstractMarkwonPlugin 基类

所有钩子方法的空实现，子类只需重写关心的方法：

```java
public abstract class AbstractMarkwonPlugin implements MarkwonPlugin {
    @Override public void configure(@NonNull Registry registry) { }
    @Override public void configureParser(@NonNull Parser.Builder builder) { }
    @Override public void configureTheme(@NonNull MarkwonTheme.Builder builder) { }
    // ... 其余方法同理
    @Override public String processMarkdown(@NonNull String markdown) {
        return markdown;  // 唯一有默认行为的方法
    }
}
```

### 5.3 CorePlugin — 核心节点处理

`CorePlugin` 是 Markwon 内置必装插件，注册了标准 Markdown 所有基础元素的处理：

| 注册的 Node 类型 | 处理内容 |
|-----------------|----------|
| `Text` | 文本追加 + OnTextAddedListener 回调 |
| `Heading` | 标题文字 + HeadingSpanFactory |
| `Link` | 链接 + 图标处理 |
| `StrongEmphasis` | 粗体 |
| `Emphasis` | 斜体 |
| `BlockQuote` | 引用块 |
| `FencedCodeBlock` | 围栏代码块 + 语法高亮 |
| `IndentedCodeBlock` | 缩进代码块 |
| `Code` | 行内代码 |
| `ListItem` / `OrderedList` / `BulletList` | 有序/无序列表 |
| `ThematicBreak` | 分割线 |
| `SoftLineBreak` / `HardLineBreak` | 换行 |
| `Paragraph` | 段落 |
| `Image` | 图片（需外部插件注册 SpanFactory） |

### 5.4 Plugin 注册与执行顺序

`MarkdownParserFactory.getDefaultPlugins()` 组装的默认插件链（**顺序有意义**）：

```
1. linkPlugin          — 自定义 LinkClickSpan
2. imagePlugin         — 图片加载 + 点击
3. htmlPlugin          — 自定义 HTML 标签处理
4. MovementMethodPlugin — MarkdownAwareMovementMethod
5. JLatexMathPlugin    — LaTeX 公式
6. SyntaxHighlightPlugin — 代码高亮
7. StrikethroughPlugin — 删除线
8. printStreamPlugin   — 流式输出文本（AfmTextPlugin）
9. TaskListPlugin      — 任务列表
10. definitationPlugin — 定义列表
11. TablePlugin        — GFM 表格
```

`MarkdownParser.init()` 还会追加：
```
12. CorePlugin         — 核心节点处理
13. CodeBlockPlugin    — 代码块标题栏/复制按钮
14. InlineParser 扩展   — 内联语法增强
15. 预处理插件          — LaTeX 占位符转换
```

## 七、设计思想总结

### 7.1 Plugin 链式架构

所有功能都是 Plugin，包括核心功能（`CorePlugin`）。扩展新功能不需要修改框架代码，只需实现 `MarkwonPlugin` 接口。

### 7.2 工厂模式分离关注点

- **SpanFactory** 负责创建 Span 对象，与 Node 遍历逻辑解耦
- **NodeVisitor** 负责 AST 遍历和文本追加，与 Span 创建解耦
- 两者通过 `MarkwonSpansFactory` 和 `MarkwonVisitor.Builder` 分别注册

### 7.3 预处理链

某些 Markdown 扩展语法无法在 CommonMark Parser 层面支持（如 `\[\]` LaTeX、highlight 标签），通过 `processMarkdown()` 钩子在解析前做文本替换。

### 7.4 两层 Plugin 组合

- **MarkdownParserFactory** — 组装业务级插件（链接点击、图片加载、HTML 处理等）
- **MarkdownParser** — 追加引擎级插件（CorePlugin、CodeBlock、InlineParser）

这种分层让业务层和引擎层各自独立管理插件。

### 7.5 流式渲染兼容

通过 `StreamOutStateObserver` 接口，让 TablePlugin、LaTeX Plugin 等感知当前是否处于流式输出状态，从而调整缓存策略和重建时机。
