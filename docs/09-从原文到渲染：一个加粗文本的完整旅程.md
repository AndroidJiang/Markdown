# 从原文到渲染：一个加粗文本的完整旅程

> 本文档以最简单的 `**Hello**` 为例，逐行追踪从原始字符串输入到最终在 TextView 上显示加粗文字的**每一步**。目的不是讲表格、LaTeX 这些复杂场景，而是帮你建立对 AntFluid 整体渲染流水线的直觉理解。
>
> 掌握了这条链路后，你面对任何 Markdown 元素（表格、代码块、图片…），都能用同样的思路去追踪它经过了哪些 Plugin、哪些 Visitor、生成了什么 Span。

---

## 一、全局时序图

## 二、逐步详解

### 阶段 0：初始化（只执行一次）

在你调用 `setMarkdownText()` 之前，`init()` 已经完成了整个引擎的搭建：

```java
// PrinterMarkDownTextView.java
public void init(MarkdownStyles styles, ElementClickEventCallback callback) {
    mMarkdownParser = MarkdownParserFactory.create(getContext(), this, styles, callback);
}
```

`MarkdownParserFactory.create()` → `MarkdownParser` 构造函数 → `init()` 做了这些事：

```
1. 收集 MarkdownParserFactory 提供的"业务级"插件
   → linkPlugin, imagePlugin, htmlPlugin, TablePlugin, TaskListPlugin ...

2. 收集 MarkdownParser 自身的"引擎级"插件
   → CorePlugin, CodeBlockPlugin, InlineParserPlugin, 匿名预处理 Plugin

3. 合并所有 Plugin 列表

4. Markwon.builderWithPlugs(context, allPlugins)
   → 遍历每个 Plugin 调用：
       configureParser(parserBuilder)         → 注册 CommonMark 扩展
       configureVisitor(visitorBuilder)       → 注册 Node → Visitor 映射
       configureSpansFactory(spanFactoryBuilder) → 注册 Node → SpanFactory 映射
       configureTheme(themeBuilder)           → 修改主题
   → 构建不可变的 Parser, Visitor, SpanFactory, Theme
   → 返回 MarkwonImpl 实例

5. 保存 mMarkwon 供后续使用
```

**对 `**Hello**` 关键的注册发生在 `CorePlugin.configureSpansFactory()` 中：**

```java
// CorePlugin.java
builder.setFactory(StrongEmphasis.class, new StrongEmphasisSpanFactory());
```

以及 `CorePlugin.configureVisitor()` 中：

```java
// CorePlugin.java → strongEmphasis()
builder.on(StrongEmphasis.class, (visitor, strongEmphasis) -> {
    final int length = visitor.length();     // 记录当前文本长度作为起点
    visitor.visitChildren(strongEmphasis);    // 遍历子节点（追加文本）
    visitor.setSpansForNodeOptional(strongEmphasis, length); // 回填 Span
});
```

> **设计要点：** 注册发生在构建阶段，运行时只做查表，不再动态创建 Visitor/Factory。

---

### 阶段 1：预处理 — `processMarkdown()`

```java
// MarkwonImpl.java
public Node parse(String input) {
    for (MarkwonPlugin plugin : plugins) {
        input = plugin.processMarkdown(input);   // 每个 Plugin 依次处理
    }
    return parser.parse(input);
}
```

| Plugin | 对 `"**Hello**"` 做了什么 |
|--------|--------------------------|
| linkPlugin | 原样返回（AbstractMarkwonPlugin 默认） |
| imagePlugin | 原样返回 |
| htmlPlugin (CustomHtmlPlugin) | 处理 `highlight`、`\[\]` 等，与 `**` 无关，原样返回 |
| CorePlugin | 没有重写 processMarkdown，走默认原样返回 |
| 匿名 LaTeX Plugin | 正则 `\$\{1,2\}\s*\\bm\{...\}` 不匹配，原样返回 |
| InlineParserPlugin | 原样返回 |

**结果：** 经过所有 Plugin 后，文本仍然是 `"**Hello**"`，一个字符都没变。

> **什么时候会变？** 比如输入 `\[x^2\]`，CustomHtmlPlugin 会把它转成 `$$x^2$$`。或者输入 `$\bm{X}$`，匿名 Plugin 会转成 `***X***`。

---

### 阶段 2：解析 — CommonMark Parser 生成 AST

```java
return parser.parse("**Hello**");
```

CommonMark 的 InlineParser 识别 `**...**` 包裹的内容为 `StrongEmphasis` 节点。

生成的 AST 树结构：

```
Document
└── Paragraph
    └── StrongEmphasis          ← ** 包裹
        └── Text("Hello")      ← 纯文本内容
```

> **类比理解：** 这就像 HTML 解析器把 `<b>Hello</b>` 解析成 DOM 树一样。CommonMark 把 Markdown 语法解析成了 Node 树。每种语法元素对应一个 Node 类：
> - `#` → `Heading`
> - `> ` → `BlockQuote`
> - `**` → `StrongEmphasis`
> - `*` → `Emphasis`
> - `` ` `` → `Code`
> - `|---|` → `TableBlock`

---

### 阶段 3：渲染前钩子 — `beforeRender()`

```java
// MarkwonImpl.java
public Spanned render(Node node) {
    for (MarkwonPlugin plugin : plugins) {
        plugin.beforeRender(node);    // 可以在这里修改 AST 结构
    }
    // ...
}
```

大多数 Plugin 的 `beforeRender` 是空实现。少数 Plugin（如 TablePlugin）会在这里做 AST 清理。

**对 `**Hello**`：** 无任何 Plugin 修改 AST，树结构不变。

---

### 阶段 4：Visitor 深度遍历 AST — 核心中的核心

这是整个流程最重要的阶段。让我们逐个节点跟踪：

```java
// MarkwonImpl.java
final MarkwonVisitor visitor = visitorFactory.create();
node.accept(visitor);     // 从 Document 根节点开始深度遍历
```

#### 第 1 步：进入 Document

```java
// MarkwonVisitorImpl.java
private void visit(Node node) {
    NodeVisitor nodeVisitor = nodes.get(node.getClass()); // 查表：Document.class
    if (nodeVisitor != null) {
        nodeVisitor.visit(this, node);
    } else {
        visitChildren(node);     // Document 没有注册 Visitor → 默认遍历子节点
    }
}
```

Document 没有专门的 Visitor → 直接 `visitChildren(Document)`。

#### 第 2 步：进入 Paragraph

Paragraph 有注册 Visitor（CorePlugin 中）：

```java
// CorePlugin.java → paragraph()
builder.on(Paragraph.class, (visitor, paragraph) -> {
    final boolean inTightList = /* 判断是否在紧凑列表中 */;
    if (inTightList) { /* 紧凑列表不加段落间距 */ }

    final int length = visitor.length();     // 0
    visitor.visitChildren(paragraph);         // → 进入 StrongEmphasis
    visitor.setSpansForNodeOptional(paragraph, length);
});
```

此时 `visitor.length() = 0`（SpannableBuilder 还是空的）。

调用 `visitChildren(paragraph)` → 进入 StrongEmphasis。

#### 第 3 步：进入 StrongEmphasis ← 关键！

```java
// CorePlugin.java → strongEmphasis()
builder.on(StrongEmphasis.class, (visitor, strongEmphasis) -> {
    final int length = visitor.length();     // length = 0（当前 builder 长度）
    visitor.visitChildren(strongEmphasis);    // → 进入 Text("Hello")
    visitor.setSpansForNodeOptional(strongEmphasis, length);  // 回填 Span
});
```

**第 3a 步：** `visitor.length()` = 0，记住这个起点。

**第 3b 步：** `visitChildren(strongEmphasis)` → 进入子节点 Text。

#### 第 4 步：进入 Text("Hello")

```java
// CorePlugin.java → text()
builder.on(Text.class, (visitor, text) -> {
    visitor.builder().append(text.getLiteral());   // builder.append("Hello")
    // ... onTextAddedListeners 通知
});
```

执行完后，`SpannableBuilder` 的内容变为：

```
builder 文本: "Hello"
builder 长度: 5
已注册 Span: (无)
```

#### 第 5 步：回到 StrongEmphasis — 回填 Span

Text 访问完毕，控制权回到 StrongEmphasis 的 Visitor：

```java
visitor.setSpansForNodeOptional(strongEmphasis, length);  // length = 0
```

内部执行：

```java
// MarkwonVisitorImpl.java
public void setSpansForNodeOptional(Node node, int start) {
    SpanFactory factory = configuration.spansFactory().get(node.getClass());
    // 查表：StrongEmphasis.class → StrongEmphasisSpanFactory ✓ 找到了！
    if (factory != null) {
        setSpans(start, factory.getSpans(configuration, renderProps));
    }
}
```

调用 `StrongEmphasisSpanFactory.getSpans()`：

```java
// StrongEmphasisSpanFactory.java
public Object getSpans(MarkwonConfiguration configuration, RenderProps props) {
    return new StrongEmphasisSpan();    // 创建加粗 Span 对象
}
```

然后设置到 SpannableBuilder：

```java
// MarkwonVisitorImpl.java
public void setSpans(int start, Object spans) {
    SpannableBuilder.setSpans(builder, spans, start, builder.length());
    // → setSpan(new StrongEmphasisSpan(), 0, 5)
}
```

执行完后，`SpannableBuilder` 状态：

```
builder 文本: "Hello"
builder 长度: 5
已注册 Span: [StrongEmphasisSpan, start=0, end=5]
```

#### 第 6 步：回到 Paragraph — 回填段落 Span

StrongEmphasis 处理完毕，控制权回到 Paragraph 的 Visitor：

```java
visitor.setSpansForNodeOptional(paragraph, 0);
```

查表 `Paragraph.class` → SpanFactory 返回 `null` 或段落间距 Span（这里因为是唯一的段落，通常无额外效果）。

#### 遍历完成

回到 Document → `visitChildren` 结束 → `node.accept(visitor)` 返回。

---

### 阶段 5：构建最终 Spanned

```java
// MarkwonImpl.java
final Spanned spanned = visitor.builder().spannableStringBuilder();
```

内部操作：

```java
// SpannableBuilder.java
public SpannableStringBuilder spannableStringBuilder() {
    SpannableStringBuilderReversed reversed = new SpannableStringBuilderReversed(builder);
    for (Span span : spans) {
        reversed.setSpan(span.what, span.start, span.end, span.flags);
        // → setSpan(StrongEmphasisSpan, 0, 5, SPAN_EXCLUSIVE_EXCLUSIVE)
    }
    return reversed;
}
```

**结果：** 返回一个 `SpannableStringBuilder`：
- 文本内容：`"Hello"`
- Span 列表：`[StrongEmphasisSpan @ [0, 5)]`

> **为什么用 Reversed？** Span 在 builder 中是按 push 顺序存的（后注册的在栈顶）。`SpannableStringBuilderReversed` 逆序 setSpan，确保先注册的 Span 有更高优先级（符合 Markdown 嵌套语义）。

---

### 阶段 6–8：setText 阶段

```java
// MarkwonImpl.java
public void setParsedMarkdown(TextView textView, Spanned markdown) {
    // 阶段 6: beforeSetText
    for (MarkwonPlugin plugin : plugins) {
        plugin.beforeSetText(textView, markdown);
    }

    // 阶段 7: 实际 setText
    textView.setText(markdown, bufferType);

    // 阶段 8: afterSetText
    for (MarkwonPlugin plugin : plugins) {
        plugin.afterSetText(textView);
    }
}
```

#### 阶段 6：beforeSetText

CorePlugin 做两件事：

```java
// CorePlugin.java
public void beforeSetText(TextView textView, Spanned markdown) {
    OrderedListItemSpan.measure(textView, markdown);  // 测量有序列表宽度（这里没有列表，跳过）
    TextViewSpan.applyTo(spannable, textView);         // 将 TextView 引用绑定到 Spannable
}
```

对 `"Hello"` 无实质影响。

#### 阶段 7：setText

```java
textView.setText(spanned, BufferType.SPANNABLE);
```

Android TextView 接管：
1. 内部保存 `SpannableStringBuilder` 引用
2. 触发 `requestLayout()` + `invalidate()`
3. 等待下一帧绘制

#### 阶段 8：afterSetText

CorePlugin 检查 MovementMethod：

```java
// CorePlugin.java
public void afterSetText(TextView textView) {
    if (!hasExplicitMovementMethod && textView.getMovementMethod() == null) {
        textView.setMovementMethod(LinkMovementMethod.getInstance());
    }
}
```

对 `"Hello"` 无视觉影响（但保证后续链接可点击）。

---

### 阶段 9：Android 绘制 — Span 生效

当 Android 的绘制管线执行到 `onDraw()` 时：

1. **测量阶段** — `Layout` 创建 `TextLine`，对每段文本检查 `MetricAffectingSpan`：

```java
// StrongEmphasisSpan.java
public void updateMeasureState(TextPaint p) {
    p.setFakeBoldText(true);    // 告诉 Paint：用伪粗体测量
}
```

`setFakeBoldText(true)` 让 Paint 在不切换字体文件的情况下，通过算法加粗笔画。文字宽度会略微增大。

2. **绘制阶段** — 绘制到 Canvas 前，再次调用：

```java
// StrongEmphasisSpan.java
public void updateDrawState(TextPaint tp) {
    tp.setFakeBoldText(true);    // 告诉 Paint：用伪粗体绘制
}
```

3. **最终效果** — `Canvas.drawText("Hello", x, y, paint)` 时，`paint.isFakeBoldText() == true`，渲染引擎用加粗笔画绘制文字。

**屏幕上，你看到了加粗的 "Hello"。**

## 三、完整数据流转表

| 步骤 | 阶段 | 数据形态 | 关键代码位置 |
|------|------|----------|-------------|
| 1 | 外部调用 | `String "**Hello**"` | `PrinterMarkDownTextView.setMarkdownText()` |
| 2 | 预处理 | `String "**Hello**"` (不变) | `MarkwonImpl.parse()` → `processMarkdown()` |
| 3 | 解析 | `AST: Document→Paragraph→StrongEmphasis→Text` | `Parser.parse()` |
| 4 | beforeRender | AST (不变) | `MarkwonImpl.render()` |
| 5a | 遍历 Text | SpannableBuilder: `"Hello"` | `CorePlugin.text()` |
| 5b | 遍历 StrongEmphasis | SpannableBuilder: `"Hello"` + `StrongEmphasisSpan@[0,5)` | `CorePlugin.strongEmphasis()` |
| 6 | 构建 Spanned | `SpannableStringBuilder("Hello")` + Span | `SpannableBuilder.spannableStringBuilder()` |
| 7 | beforeSetText | 测量/绑定 | `CorePlugin.beforeSetText()` |
| 8 | setText | TextView 持有 Spanned | `textView.setText()` |
| 9 | 绘制 | 加粗 "Hello" 像素 | `StrongEmphasisSpan.updateDrawState()` |

## 四、举一反三：其他元素走的是同一条路

理解了 `**Hello**` 的链路后，其他元素只是在各阶段的**具体行为**不同，**流程结构完全一样**：

### 斜体 `*Hello*`

```
AST: Document → Paragraph → Emphasis → Text("Hello")
Visitor: CorePlugin.emphasis() → 同样的 length/visitChildren/setSpansForNodeOptional
SpanFactory: EmphasisSpanFactory → new EmphasisSpan()
Span: EmphasisSpan.updateDrawState() → paint.setTextSkewX(-0.25f)  // 斜体
```

### 标题 `# Hello`

```
AST: Document → Heading(level=1) → Text("Hello")
Visitor: CorePlugin.heading() → visitor.visitChildren + setSpansForNodeOptional
SpanFactory: HeadingSpanFactory → new HeadingSpan(theme, level)
Span: HeadingSpan.updateDrawState() → theme.getTitleStyle(1).apply(paint)
      → paint.textSize *= 1.3  // H1 放大 1.3 倍
      → paint.setFakeBoldText(true)
beforeSetText: HeadingSpan 还会影响段落间距
```

### 行内代码 `` `code` ``

```
AST: Document → Paragraph → Code → Text("code")
Visitor: CorePlugin 注册的 Code Visitor → append 文本 + setSpan
SpanFactory: CodeSpanFactory → new RoundedBackgroundSpan(theme)
Span: RoundedBackgroundSpan.draw() → 绘制圆角背景矩形 + 等宽字体文字
```

### 链接 `[text](url)`

```
AST: Document → Paragraph → Link(dest="url") → Text("text")
Visitor: CorePlugin.link() → visitChildren + setSpansForNodeOptional
SpanFactory: 被 MarkdownParserFactory.linkPlugin() 替换 → LinkClickSpan
Span: LinkClickSpan.updateDrawState() → 链接颜色/下划线
      onClick() → 触发 ElementClickEventCallback.onLinkClicked()
```

### 表格 `| a | b |`

```
processMarkdown: CustomHtmlPlugin 可能做换行修复
AST: Document → TableBlock → TableHead → TableRow → TableCell → Text
Visitor: TablePlugin.configureVisitor() 注册 → 收集 Cell 数据 → 创建 TableRowSpan
SpanFactory: TablePlugin 内部直接 setSpan（不走标准 SpanFactory）
Span: TableRowSpan.draw() → 绘制行背景、边框、各列 StaticLayout
afterSetText: TableRowsScheduler 注册图片刷新
```

### 图片 `![alt](url)`

```
AST: Document → Paragraph → Image(dest="url", alt="alt")
Visitor: CorePlugin.image() → 默认只追加 alt 文本
SpanFactory: ImagesPlugin 注册 → AsyncDrawableSpan
Span: AsyncDrawableSpan → 先显示占位 → ImageHandler 异步加载 → 加载完成触发刷新
afterSetText: AsyncDrawableScheduler 注册
```

## 五、设计思想提炼

### 5.1 三阶段分离

```
String → AST (解析) → Spanned (渲染) → 像素 (绘制)
```

每个阶段职责清晰，互不耦合：
- 解析阶段不关心怎么画
- 渲染阶段不关心语法怎么解
- 绘制阶段不关心 Markdown 是什么

### 5.2 "先记录起点，再回填 Span" 模式

几乎所有容器节点（StrongEmphasis、Heading、Link、BlockQuote…）都用同一个模式：

```java
int length = visitor.length();       // 1. 记录起点
visitor.visitChildren(node);          // 2. 子节点追加文本
visitor.setSpansForNodeOptional(node, length);  // 3. 在 [起点, 当前位置) 设置 Span
```

这是 Markwon 最核心的设计模式，理解了它就理解了所有节点的处理方式。

### 5.3 查表驱动

运行时不做类型判断（if/switch），而是在构建阶段注册好两张映射表：

```
Node类型 → NodeVisitor    （控制遍历行为）
Node类型 → SpanFactory    （控制生成什么 Span）
```

扩展新元素只需要往这两张表里添加条目，不修改框架代码。

### 5.4 Plugin 是唯一的扩展入口

所有行为都通过 Plugin 注入：

```
Plugin.configureParser()       → 添加新的解析能力（新 Node 类型）
Plugin.configureVisitor()      → 注册新 Node 的遍历行为
Plugin.configureSpansFactory() → 注册新 Node 的 Span 工厂
Plugin.processMarkdown()       → 解析前预处理文本
Plugin.beforeRender()          → 修改 AST
Plugin.afterRender()           → 渲染后处理
Plugin.beforeSetText()         → setText 前准备
Plugin.afterSetText()          → setText 后收尾
```

连 `CorePlugin`（标题、加粗、列表等基础元素）都是一个 Plugin，没有任何硬编码。
