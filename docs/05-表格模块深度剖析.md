# 表格模块深度剖析

> 本文档深入分析 AntFluid 中表格功能的完整实现，包括解析、数据结构、绘制、流式兼容和已知限制。

---

## 一、模块文件总览

表格功能涉及 `markwon-ext-tables` 模块的以下文件：

| 文件 | 职责 |
|------|------|
| `TablePlugin.java` | 表格 Markwon 插件（解析注册 + AST 遍历 + 流式缓存） |
| `TableRowSpan.java` | 表格行 `ReplacementSpan`（核心绘制） |
| `TableSpan.java` | 表格块标记 Span（空 marker） |
| `TableRowsScheduler.java` | 表格行异步刷新调度 |
| `Table.java` | TableBlock AST → 数据结构解析工具 |
| `TableBlockTitleBlockSpan.java` | 表格标题栏（放大预览按钮） |
| `TableLineSpacingSpan.java` | 表格行间距 Span |
| `TopSpacingSpan.java` | 表头上方留白 Span |
| `BaseBlockTitleSpan.java` | 块标题 Span 基类 |
| `MarkdownAwareMovementMethod.java` | 自定义 MovementMethod（链接点击） |
| `IMarkdownLayer.java` | TextView 扩展接口 |

## 二、解析流程

### 2.1 语法识别

GFM 表格语法由 `MyTablesExtension`（`TablePlugin` 内部类，基于 `commonmark-ext-gfm-tables`）解析。

```
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| A   | B   | C   |
| D   | E   | F   |
```

### 2.2 AST 结构

解析后生成的 Node 树：

```
TableBlock
├── TableHead
│   └── TableRow
│       ├── TableCell (alignment=LEFT, text="列1")
│       ├── TableCell (alignment=LEFT, text="列2")
│       └── TableCell (alignment=LEFT, text="列3")
└── TableBody
    ├── TableRow
    │   ├── TableCell (text="A")
    │   ├── TableCell (text="B")
    │   └── TableCell (text="C")
    └── TableRow
        ├── TableCell (text="D")
        ├── TableCell (text="E")
        └── TableCell (text="F")
```

### 2.3 自定义解析增强

AntFluid 的 `MyTableBlockParser` 相对标准 CommonMark GFM 扩展做了增强：

- **段落内表格**：支持 `isInParagraph` 模式，当表格跟在段落文本后面时也能识别
- **分隔符识别**：增强了 `|----|` 分隔行的匹配逻辑
- **流式场景**：处理不完整表格（最后一行未结束）的情况

## 三、Visitor 遍历流程

`TablePlugin.configureVisitor()` 注册了 4 个 Node 类型的访问器：

### 3.1 TableBlock 访问

```
进入 TableBlock
    → 记录 tableIndex（多表格计数）
    → 遍历子节点（TableHead + TableBody）
    → 退出时：
        - 设置 TableSpan 标记整个表格区间
        - 添加段落间距 Span
```

### 3.2 TableCell 访问

```
进入 TableCell
    → 记录 cell 开始位置
    → 遍历 cell 内容（文本、链接、代码等）
    → 退出时：
        - 收集 Cell(alignment, spannedText) 到 mPendingTableRow 列表
```

### 3.3 TableRow / TableHead 访问 — `visitRow()`

这是最核心的方法，负责将一行 Cell 列表转化为一个 `TableRowSpan`：

```
visitRow(visitor, node)
│
├── 追加 \u00a0（不换行空格，防 Android 的 trim 机制）
│
├── 判断是否复用缓存（流式模式）
│   ├── 流式 + 已缓存 → 复用 TableRowSpan（避免重建）
│   └── 否则 → new TableRowSpan(theme, cells, isHeader, isOdd)
│
├── 如果是表头行（header）
│   ├── TopSpacingSpan — 预留标题栏高度
│   └── TableBlockTitleBlockSpan — 标题栏（"表格" + 放大图标）
│
├── TableLineSpacingSpan — 行间距
│
└── TableRowSpan — 核心绘制 Span
```

## 四、TableRowSpan 绘制详解

`TableRowSpan extends ReplacementSpan` 是表格绘制的核心。

### 4.1 数据结构

```java
public class TableRowSpan extends ReplacementSpan {
    // 单元格数据
    public static class Cell {
        Alignment alignment;  // LEFT, CENTER, RIGHT
        CharSequence text;    // 可含内联 Span
    }

    private final List<Cell> cells;    // 当前行所有单元格
    private final boolean header;       // 是否表头行
    private final boolean odd;          // 奇偶行（交替背景色）
    private StaticLayout[] layouts;     // 各列的文本 Layout
    private int totalRows;             // 表格总行数（用于最后一行圆角）
}
```

### 4.2 测量流程 — `getSize()`

```
getSize(paint, text, start, end, fm)
│
├── 获取 TextView 最大宽度
│   └── IMarkdownLayer.getViewMaxWidth()
│
├── 首次或宽度变化 → makeNewLayouts()
│   ├── 列宽 = 总宽 / 列数
│   ├── 每列创建 StaticLayout(cellWidth - padding*2)
│   └── 记录最大行高 maxHeight
│
├── 设置 FontMetricsInt
│   ├── fm.ascent = -(maxHeight + padding)
│   └── fm.descent = 0
│
└── 返回 Math.min(1, ret - leading)
    // 返回 ~1px 宽度的占位
    // 实际宽度由 draw() 中撑开整行
```

### 4.3 绘制流程 — `draw()`

```
draw(canvas, text, start, end, x, top, y, bottom, paint)
│
├── 1. 布局重建判断
│     recreateLayouts(spanWidth, x)
│     → 宽度变化则 makeNewLayouts()
│     → x 重置为 0（ReplacementSpan 整行绘制）
│
├── 2. 表头偏移
│     if (header && !isHideHeader)
│       top += titleBarHeight  // 标题栏高度
│
├── 3. 行背景绘制
│     ├── header → applyTableHeaderRowStyle（表头背景色）
│     ├── odd → 奇数行背景色
│     ├── even → 偶数行背景色
│     ├── 最后一行 → drawRectWithBottomRound（底部圆角）
│     └── isHideHeader + header → clip 顶部圆角
│
├── 4. 边框绘制 (drawBorder && borderWidth > 0)
│     ├── 首行顶线
│     │   └── 查找 TableSpan 位置 → LeadingMarginUtils.selfStart
│     ├── 非末行 → bottom 横线
│     ├── 末行 → drawLineWithBottomRound（圆角底边框）
│     └── 各列竖线
│         ├── i==0 → 左竖线
│         ├── i==last → 右竖线（含 roundingDiff 修正）
│         └── 中间 → 列间竖线
│
├── 5. 单元格文本绘制（循环 layouts）
│     for (i = 0; i < layouts.length; i++) {
│         canvas.save()
│         canvas.translate(x + i * cellWidth, top)
│         // 绘制列间竖边框
│         canvas.translate(leftRightPadding, topBottomPadding + heightDiff)
│         // heightDiff 实现垂直居中
│         layouts[i].draw(canvas)  // StaticLayout 绘制
│         canvas.restore()
│     }
│
└── 6. 高度变化检测
      if (newHeight != prevHeight)
        invalidator.invalidate()  // 触发 TextView 重绘
```

### 4.4 StaticLayout 创建

每个单元格创建独立的 `StaticLayout`：

```java
private StaticLayout makeLayout(Cell cell, int cellWidth) {
    CharSequence text = cell.text;
    TextPaint tp = new TextPaint(paint);
    // 应用表格文字样式
    theme.applyTableTextStyle(tp, header);

    return new StaticLayout(
        text,
        tp,
        cellWidth,
        alignmentFromCell(cell.alignment),
        1.0f,    // spacingMultiplier
        0.0f,    // spacingAdd
        true     // includePad
    );
}
```

## 五、标题栏与交互

### 5.1 TableBlockTitleBlockSpan

继承 `BaseBlockTitleSpan`，在表头行上方绘制标题栏：

```
┌─────────────────────────────┐
│ 表格    [🔍放大按钮]          │  ← TableBlockTitleBlockSpan
├─────┬─────┬─────────────────┤
│ 列1 │ 列2 │ 列3             │  ← TableRowSpan (header)
├─────┼─────┼─────────────────┤
│ A   │ B   │ C               │  ← TableRowSpan (body, odd)
├─────┼─────┼─────────────────┤
│ D   │ E   │ F               │  ← TableRowSpan (body, even)
```

### 5.2 TopSpacingSpan

在表头行上方预留 `titleBarHeight` 高度，供 `TableBlockTitleBlockSpan` 绘制。

## 六、流式渲染兼容

### 6.1 问题

流式输出时，表格内容逐行到达。如果每次都重建 `TableRowSpan`，会导致闪烁和性能问题。

### 6.2 解决方案

`TablePlugin` 实现 `StreamOutStateObserver` 接口：

```java
@Override
public void onStreamOutStateChanged(boolean isPrinting) {
    if (!isPrinting) {
        // 流式结束，清空缓存
        visitor.mTableSpanCache.clear();
    }
}
```

流式模式下：
- `mTableSpanCache` 按 `(tableIndex, length)` 缓存 `TableRowSpan`
- 如果当前行内容未变，复用缓存的 Span
- 新行到达时才创建新 Span

### 6.3 不完整行判断

```java
// 通过原始 markdown 判断最后一行是否完整
boolean findCurrentTableEnd(int tableIndex) {
    String md = originMarkdown;
    int lastPipe = md.lastIndexOf("|\n|");
    // 如果最后一个 | 后面没有换行+|，说明最后一行不完整
    return lastPipe >= 0 && lastPipe < md.length() - 3;
}
```

## 七、异步刷新调度

### TableRowsScheduler

当表格单元格中包含图片（`AsyncDrawableSpan`）时：

1. 图片异步加载完成
2. `Invalidator.invalidate()` 被调用
3. `TableRowsScheduler` 合并多个 invalidate 请求
4. 统一 `post(setText)` 刷新 TextView

这避免了每张图片加载完成都触发一次完整的 setText。

## 八、已知限制

| 限制 | 原因 | 影响 |
|------|------|------|
| 列宽均分 | `getSize()` 中 `width / columns` | 内容长短差异大时浪费空间 |
| 不支持 colspan/rowspan | CommonMark GFM 标准不支持 | 合并单元格无法渲染 |
| 表格内链接不可点击 | `ReplacementSpan` 内的 `StaticLayout` 不传递 touch 事件 | 需要自定义 MovementMethod |
| 不支持横向滚动 | `ReplacementSpan` 受 `TextView` 宽度约束 | 多列表格被压缩 |
| 流式不完整行判断启发式 | 依赖 `lastIndexOf("|\n|")` | 复杂嵌套可能误判 |
| 长表格性能 | 每行一个 `StaticLayout`，多行时内存较大 | 超长表格卡顿 |

### egame_cloud_phone 中已解决的问题

| 问题 | egame 解决方案 |
|------|---------------|
| 表格内链接不可点击 | `TableRowSpan.handleCellLinkClick()` + `NonScrollingLinkMovementMethod` |
| 单元格内 ReplacementSpan 不折行 | `sanitizeTableCellText()` 清理特殊 Span |
| RecyclerView 复用截断 | 非流式时 `clear()` 清全部缓存 |
| 长链接撑破列宽 | `compactTableLinkText()` 截断链接文本 |

## 十、修改表格的快速参考

### 只改外观 → 修改 TableStyle

```java
MarkdownStyles styles = MarkdownStyles.getDefaultStyles();
styles.tableStyle()
    .tableBlockRadius(16)            // 圆角
    .borderColor(0xFFDDDDDD)         // 边框色
    .borderWidth(1)                   // 边框宽度
    .header().backgroundColor(0xFFF5F5F5)  // 表头背景
    .body().fontColor(0xFF444444);         // 正文字色
```

### 改绘制行为 → 修改 TableRowSpan

修改 `draw()` 方法中对应部分：
- 背景 → 第 3 步
- 边框 → 第 4 步
- 文字 → 第 5 步
- 布局 → `makeNewLayouts()` / `makeLayout()`

### 改解析行为 → 修改 TablePlugin

- 数据收集 → `visitRow()` / `TableCell` 访问器
- 流式缓存 → `getCachedSpan()` / `cacheSpan()`
- 标题栏 → `isHideHeader` 参数
